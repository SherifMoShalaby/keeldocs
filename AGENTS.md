# keeldocs - agent instructions (universal fallback block)

This repo is managed by keeldocs (living-documentation drift detection). If your agent supports Agent Skills, the installed keeldocs skills take precedence over this file - your agent's own skills directory (`.claude/skills/`, `.agents/skills/`, `.cursor/skills/` and equivalents), not this repository's `skills/` source tree.

- Docs status: run `keeldocs check --json`, or `npx keeldocs check --json` if `keeldocs` is not on `PATH` - the documented `npx keeldocs init` install leaves no binary behind, so that is the normal case. A `command not found` is an invocation problem and never a reason to answer from your own reading of the code. (stdout is a <=8KB JSON envelope with a <=300-char `summary`.)
- `check` emits exactly five codes and no others: `CLEAN` (exit 0), `DRIFT_FOUND` (1, sections are stale/dead/tampered), `UNREADABLE` (1), `TOOL_ERROR` (2) and `CONFIG` (2, keeldocs.toml could not be read or `--live` was refused in CI). Treat a code you do not recognise as UNREADABLE is treated below - report it, never as clean.
- `UNREADABLE` from `check` (exit 1) means the engine declined to look at part of the repository and therefore has NO drift verdict for the run: an unparseable marker, a section it cannot verify, an anchored document outside every scan root, or a decisions-journal line it cannot read. It is not CLEAN and it is not drift. Report what the envelope names - `data.refused`, `data.unverified`, `data.unscanned`, `data.journalMalformed` each name the thing by document and line - and fix those before trusting any drift count. `data.skipped` and `data.excludedDocs` are the quieter half of the same disclosure: blind spots the repository or the user's own `exclude-paths` chose, named but never moving the exit code.
- `TOOL_ERROR` from `check` means the extractors could not run - it is NOT evidence that the docs are fine and it is NOT a task you failed. Run `keeldocs doctor --json` and report its `next` array: that is the exact install command for this machine, usually the Python extractor runtime. `doctor` emits four codes: `READY` (exit 0), `BLOCKED` (1, a hard prerequisite is missing - node below the engines floor, no python3, or no git), `TOOL_ERROR` (2, doctor itself failed) and `DEGRADED` (3, the run is degraded but usable - some providers cannot run, so the answer is partial rather than wrong). `doctor` is the only command that returns 3; `check` never does.
- NEVER edit content between `<!-- keeldocs:gen -->` markers by hand - regenerate via the CLI.
- Prose for docs goes through `keeldocs slot-write` only; the tool applies draft labels, never the model.
- Never read `.env` values; key names come from `.env.example` or the engine's value-blind extractor.
- Do not assert inferred rationale as fact; inferred content carries a visible label.
