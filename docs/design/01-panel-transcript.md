# Deliverable 1 — Panel Transcript

Nine independent senior experts reviewed the brief without sight of each other's positions, each verifying decision-critical external facts by web search (July 29, 2026). A chair then surfaced the conflicts and ran a rebuttal round on the two sharpest ones. This document records concerns, veto conditions, the ballot, and every disagreement with its resolution. Nothing was papered over; where the chair overrode an expert, the reasoning is stated.

> **Working name.** "docsmith" is used throughout as a codename. The PM verified the name is taken on npm (AGPL-3.0 project) and PyPI (GPLv3+). **Resolved 2026-07-30: the shipped name is "keeldocs"** (npm + PyPI + GitHub verified free). The first pick "undrift" was invalidated the same day — an existing company ships a CLI named `undrift` through its own Homebrew tap — validating the R14 sweep discipline.

## 1. Each expert's top concerns and veto conditions (condensed, positions preserved)

### Principal Systems Architect
Concerns: (1) "Precedence + confidence scoring" as framed is how determinism dies — any float score or iteration-order tie-break produces different graphs across runs/OSes, and since drift = diff(facts, anchors), nondeterministic resolution manufactures phantom drift. (2) Incremental extraction is absent from the provider contract and cannot be retrofitted — providers must declare input globs on day one or cache invalidation is undecidable. (3) Unversioned anchor-hash algorithms are a mass-false-drift bomb: a grammar upgrade flags 500 docs stale. Vetoes: float confidence; derived artifacts committed as canonical truth; any LLM call in the drift/verify path; providers with undeclared I/O; MCP-only distribution; unversioned hash algorithms.

### Static Analysis / Compilers Engineer
Concerns: (1) The brief's anchor example (`OrderService.submit@a3f1b2`) conflates identity with content and 24-bit hashes birthday-collide at ~4k facts. (2) Provider identity will contaminate drift: switching `migrations→live` or upgrading a provider must not mark the repo stale — provider name/version belongs in provenance outside the hashed payload. (3) "tree-sitter-imports" oversells tree-sitter: it is syntax-only, import *resolution* needs per-ecosystem code, and github/stack-graphs (the name-binding attempt) was archived Sep 2025 (verified). Vetoes: line-number anchors; content-derived identity; drift over raw bytes or LLM text; regex-over-lines as the declarative tier; requiring SCIP indexer toolchains; silent auto-rebind; extraction failure reported as drift.

### Developer Experience Architect
Concerns: (1) Retention cliff — a drift tool is structurally silent its first month; Swimm's correct thesis died of no daily consumption habit (verified: Swimm has pivoted to legacy-modernization services). (2) Noise death spiral — doc-relevant churn outpaces dependency bumps; a Dependabot study (verified) found 11.3% of projects deprecated it largely over volume/trust. (3) Conceptual surface exceeds the promise — nine commands plus provider/recipe/anchor vocabulary is a bigger mental model than "docs that stay true." Vetoes: fragile anchors a human can corrupt irreparably; default-on blocking CI; MCP-primary; LLM required inside init's first five minutes; >5 commands.

### AI/Agent Engineer
Concerns: (1) The brief's §3.7 distribution premise is ~9 months stale — Agent Skills (SKILL.md) is now a multi-vendor open standard natively consumed by Claude Code, Codex, Cursor, Gemini CLI, Copilot and ~25 more (verified); per-agent command mirrors are wasted surface. (2) "Continuous" accuracy vs episodic agent sessions — without a headless CLI with exit codes, docs rot exactly as feared. (3) An LLM boundary enforced in prompts instead of tools is decorative — weak local models will ignore it; the boundary must be a validating CLI that can reject prose. Vetoes: MCP-primary; any path where LLM output lands without passing a deterministic validator; one SKILL.md per capability; drift requiring an LLM; interview designs that load the mined corpus into context.

### Data / Database Engineer
Concerns: (1) The brief's own db-schema model contradicts its determinism requirement: live introspection is environment-relative and time-varying; if it can *win* resolution, "same output across runs" breaks the moment two machines run the tool. (2) "Any DB incl. Mongo" collides with "never fabricate" — Mongo has no schema; sampled inference presented as verified is fabrication. (3) Cross-source type normalization (Prisma `String` vs `varchar(255)`) is the silent noise generator; needs a versioned per-dialect canonicalization spec. Vetoes: bundling a JVM (SchemaCrawler) or the non-OSS Atlas binary; LLM anywhere in schema-fact extraction; committing environment state unlabeled; silently discarding a disagreeing schema source; sample-inferred Mongo rendered "verified."

### Platform / DevOps Engineer
Concerns: (1) Topology is env-dependent (helm values, kustomize overlays, compose profiles) and the brief models it as a single truth — a silently chosen variant poisons the "deterministic diagrams are always accurate" credibility anchor. (2) The CI drift gate will be killed by CI reality (flaky, slow, credential-hungry → `continue-on-error` within a month) unless deterministic-only, incremental, and budget-enforced. (3) Committed derived artifacts are merge-conflict machines in monorepos. Vetoes: any committed tool-mutated file that ordinary PRs must update; LLM or live DB in default CI; hard-fail coverage thresholds; conflating compose services with owned services; MCP-only; inventing a portfolio manifest where catalog-info.yaml + OpenAPI/AsyncAPI cover the seam.

### Security Engineer
Concerns: (1) Generated artifacts are a secret-exfiltration channel with no write barrier in the brief — env surfaces, DB errors embedding DSNs, git-history mining resurrecting purged keys into fresh committed markdown. (2) Code providers are arbitrary code execution with no sandbox contract, in an ecosystem that just produced a self-replicating npm worm (Shai-Hulud, CISA alert — verified). (3) Docsmith teaches agents to read attacker-influenceable files (anchors, fact files, mined PR text) as trusted metadata — a purpose-built indirect prompt-injection channel the brief never mentions. Vetoes: reading `.env` values into context or state; row-data sampling as default; auto-fetch/execute of third-party providers; credentials persisted anywhere; free-text "notes for the agent" fields in anchors; network-by-default providers; telemetry by default.

### Technical Writer / Docs Architect
Concerns: (1) BRD/PRD recipes are a category error that structurally violates "never fabricate" — business intent precedes and is not recoverable from code; reverse-engineered "requirements" enshrine bugs as intent. (2) Volatile metadata inside doc anchors (`last_verified_sha`, `confidence`, `human_edited`) makes docsmith the diff-noise generator it fears — every sync touches every section. (3) Patch-not-rewrite is demanded but no writing model is specified, so LLM re-prose will thrash diffs. Vetoes: BRD/PRD in any version; rendered inferred prose without a visible label; volatile machine state committed in doc bodies; whole-document regeneration as default; tier badges on every verified fact.

### Open Source Maintainer / PM
Concerns: (1) Platform before product — 9 capabilities, ~40 providers, 11 recipes, 5 adapters and portfolio mode before one loop is proven is the classic OSS death. (2) The wow/retention contradiction is unresolved in the brief: drift is worth nothing on day one; generation is where DeepWiki/Mintlify already play. (3) Contribution economics are assumed, not designed — community providers arrive only if time-to-first-merged-provider is ~2 hours with a fixture harness. Vetoes: any hosted service in the core path; unlabeled or auto-merged LLM output; portfolio mode in v0.1 or shaping core schemas; an interface where the easy 80% requires code; AGPL/copyleft core or mandatory CLA; launch blocked on >2 adapters; shipping under the name "docsmith" (npm + PyPI taken — verified).

## 3. Disagreements, argued and resolved

**D1 — Committed index vs never-commit-derived** (Compilers vs Platform; both vetoes engaged). Compilers: tombstones ("intentionally removed"), rebind history and rejection memory must survive doc deletion and fresh clones, else users get re-prompted forever — a noise bug. Platform: any committed file that routine runs mutate is a merge-conflict machine; veto. **Rebuttal round → synthesis accepted by both:** volatile index stays gitignored (rebuildable); a small committed **append-only decisions journal** (`.docsmith/decisions.jsonl`) holds *only durable human decisions* — tombstones, rejections, snoozes, waivers, and accepted rebind adjudications. Refinements both sides attached and the chair adopted: entries keyed on durable IDs (never volatile hashes), JCS-canonical one object per line, `merge=union` via `.gitattributes` written by init, revocation-by-new-entry, read-only in CI *enforced by the tool*, compaction only via an explicit reviewable `gc` PR, and no facts/hashes in the journal ever ("the lockfile by the back door"). Compilers' verdict: "strictly better than my committed index." → ADR-006.

**D2 — Live DB in v0.1** (Data vs PM). PM: cut entirely — credential handling is the highest-support-cost class and triggers enterprise security review; migrations/ORM parsing covers most repos. Data: live introspection is the brownfield bootstrap for no-schema-source repos, the only channel that catches out-of-band prod drift (a core product claim), and powers the Supabase RLS access-matrix — a differentiator no wrapped tool ships (Prisma skips RLS, Atlas paywalls it — both verified). **Rebuttal round → converged compromise:** ship a **Postgres-wire-only live provider (covers Supabase), wrapping tbls, behind an explicit `--live` flag**, DSN from a named env var per the Security rails, catalog-queries-only, nothing persisted — and **off the critical path**: if the security rails aren't merged by cut date it ships as v0.1.1 and nothing else slips. Static `CREATE POLICY` parsing from `supabase/migrations/*.sql` ships regardless as the degraded, labeled fallback. MySQL/SQLite/Mongo live: v0.3. → ADR-005, ADR-012.

**D3 — Language scope of v0.1** (PM vs the default assumption of TS+Python). PM: every language doubles the fixture surface; TS/JS is the largest agent-user population. Rebuttal: PM accepted the chair's precise framing — **v0.1 = TS/JS tree-sitter work end-to-end plus all language-agnostic providers** (git-log, workspace/compose parsing, SQL-DDL/migrations parsing — these never were language-bound); **Python is THE v0.2 headline**, gated on a green Python fixture matrix and drift FP <10% on two real Python repos. Chair adopted.

**D4 — MCP: thin adapter later vs never** (AI-Eng vs several "hybrid later" votes). AI-Eng: the Agent Skills standard already ate MCP's cross-agent-reach argument for this category; a "hybrid at launch" yields two half-maintained channels; token arithmetic shows idle sessions ~6× cheaper with skills. Others: keep MCP as a thin later adapter for shell-less surfaces. **Chair ruling:** no MCP code through v0.2; a v0.3 *decision point* exists only if a concrete shell-less surface with real users demands it, and any shim must be generated from the CLI's command table, never hand-maintained. This is 90% of AI-Eng's position; the residual disagreement is recorded, not hidden.

**D5 — What the first-run wow is** (map artifacts vs lie-detector). Most experts: deterministic system map + ERD + endpoint inventory, every fact source-linked. DX (seconded by Platform): rendered diagrams are 2026 table stakes — the visceral wow is the **doc lie-detector**: "your README references `scripts/setup.sh`, deleted in `8f21ac9` four months ago; documents `REDIS_URL`, read nowhere." **Resolution: both, in one `init` run, zero LLM calls** (Systems Architect's "zero-LLM wow" bait drew no objectors and three independent endorsements). The lie-detector demonstrates the thesis — verification, not generation — on first contact; the committed map artifacts seed the corpus so `sync` has a job next week. → ADR-012.

**D6 — Should portfolio needs shape v0.1 schemas?** (Platform's "v0.1 hook" vs PM's "founder-bias god-schema" warning). Resolution: the only v0.1 obligation is that fact schemas are *versioned* — required for drift anyway. The `export --backstage` projection and exposes/consumes envelope are v0.3 code. PM's warning is upheld; Platform's no-rework goal is satisfied because the portfolio join keys (endpoints, topics, env vars, DB refs) are exactly what capabilities already extract. → ADR-011.

**D7 — Row sampling: delete forever vs opt-in** (Security vs Data). Resolved without forcing: Data's Mongo sampling infers *shape* (field names, type unions), not values; Security's veto targeted *values* in committed artifacts. Ruling: sampling is opt-in (`--sample`), output is shape-only under an explicit **OBSERVED** tier ("sampled N docs at T; fields may be missing"), raw values never leave the process, example values are always synthesized from types/enums/CHECK constraints. Security's veto line, as written, passes.

**D8 — Who is the primary reader?** DX's bait ("the agent, not the human — Swimm's fate is what optimizing for human readers got the last team") vs the Technical Writer. Less conflict than advertised: TW independently wrote "agents are now a first-class reader." Ruling: dual-audience with a division of labor — retrieval structures (index, fact files, envelopes) optimize for agents; rendered markdown optimizes for humans; neither is sacrificed to the other. Swimm's actual killers (proprietary fragility, new surface, no daily consumer) are addressed by regenerable anchors, no new surface, and the agent as daily consumer.

**D9 — Community code providers in v0.1** (Security: first-party only, "one Shai-Hulud-style provider incident kills the premise" vs PM: contribution funnel is existential). Ruling: both satisfied by splitting the tiers — v0.1 accepts community **declarative** providers (T0, safe-by-construction under the RE2/tree-sitter-query constraints) through ordinary repo PRs with the fixture harness; out-of-band installable **code** providers (T2) do not exist until the signing/pinning/`provider trust` machinery ships (v0.2+). The funnel is honest anyway: Compilers showed the declarative tier's real role is the decorator-shaped long tail, while flagship dynamic-registration frameworks (Express) need first-party code providers from day one.

**D10 — Coverage: gate vs ratchet vs neither** (Platform's ratchet vs DX's "never a gate, it's gameable"). Ruling: coverage is **never a hard gate** (DX/PM), ships as a **ratchet** computed against the base branch at runtime with zero committed state (Platform), with explicit waivers surfaced as visible debt. CI is report-only by default; exit-code blocking is opt-in and only for tier-1/2 deterministic contradictions. Accept-rate self-throttling (DX) is adopted as a hard spec: proposal acceptance <30% over 4 weeks → frequencies halve, announced.

**D11 — The "15 lines of YAML" contribution story** (Compilers: mostly marketing, demote it vs PM: the funnel). Ruling: the declarative tier is real but its language is **tree-sitter query files (.scm) + a small YAML capture-to-fact manifest**, not regex-in-YAML (vetoed). Its honest positioning: decorator-shaped frameworks (NestJS, FastAPI, Spring) at ≥90% recall / ≥98% precision targets; Express-class dynamic registration is a code provider from day one (declarative recall ~70% is disqualifying for a flagship). Precision outranks recall everywhere: a missing endpoint is a coverage gap; a wrong one is a lie in the flagship artifact.

**D12 — Zero LLM-calling code in v0.1** (PM's bait vs AI-Eng's slot machinery). No real conflict on inspection: the engine never calls a model in either design — the host agent *is* the model, and AI-Eng's `slot-write` is a deterministic *validator*, not an inference client. Adopted together: v0.1 ships slot-write + draft labeling (the honesty contract needs it because v0.1 recipes contain labeled prose slots), and zero model SDKs. Direct BYO-key/Ollama invocation for headless prose: v0.3.

## 4. Corrections the panel made to the brief's own premises

1. **The cited study is real but misdated and over-specified.** "AI Where It Matters" is N=860 Microsoft developers, **October 2025** (arXiv 2510.00762), not 2026; the documentation-toil demand is confirmed. The "~46%" figure and the exact "Continuous Documentation Synchronizer" name/rank could not be verified from abstracts (they likely live in the 2026 follow-up "To Copilot and Beyond") — treat as ASSUMPTION; do not put 46% in a README.
2. **§3.7's adapter model is outdated in the right direction.** Agent Skills is now a cross-vendor open standard; "adapters" shrink to installer path-maps + frontmatter strip-lists + smoke tests, not command rewrites.
3. **"Source never leaves the machine" is false as stated** when the runtime is a cloud-LLM agent that already reads source. Reworded honestly in ADR-013.
4. **Swimm didn't fail for lack of the idea** — it shipped doc-code coupling years ago and has pivoted to legacy-modernization services. The failure modes (proprietary fragility, new surface, no daily consumer) are design constraints now, and the agent-as-daily-reader is the structural change that makes the category viable in 2026.
5. **"docsmith" cannot be the shipped name** (npm: AGPL project at 0.8.4; PyPI: GPLv3+ tool).
6. **Mermaid's C4 syntax is officially experimental** — the system-map recipe emits stable flowchart syntax with C4 semantics kept in the fact layer.
7. **stack-graphs is archived** — universal name-binding on top of tree-sitter is not available off the shelf; per-ecosystem import resolvers are code, and unresolvable edges must render as labeled-unresolved, never guessed.
